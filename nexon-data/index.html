체결가 분석 후보38종
요일 추세 표시 조건 충족26/38종

2026.10.07 02:12 KST 공개 서비스 집계 기준입니다. 체결 기록 범위는 2026.08.08~10.07이며 수집 시작 시 조회한 과거 기록을 포함합니다. 체결 API가 한 번에 최근 100건까지만 제공하므로 누적 기록은 전체 거래량이 아닌 관측 하한값입니다. 연결된 서비스는 매시간 갱신됩니다.

문제

현재 최저 호가와 실제 체결가는 다르고, 체결 API는 최근 거래를 최대 100건까지만 제공합니다. 이벤트 전후의 가격과 거래량을 비교하려면 짧게 열리는 API 기록을 지속적으로 쌓고 같은 기준으로 정리해야 했습니다.

역할

품목별로 2~60분의 기본 수집 주기를 정하고, 최근 100건이 현재 수집 주기의 1.5배보다 짧은 구간에 집중되면 수집 간격을 줄이도록 설계했습니다. 원본 체결·호가와 시간 단위 집계를 PostgreSQL에 저장하고, 페이지 생성과 최신성 점검도 자동화했습니다.

판단 기준

일반 아이템은 직전 60분 체결량 가중 평균가, 카드는 강화 단계별 최저 호가를 대표값으로 사용했습니다. 빈 관측은 0으로 채우지 않았고, 취소가 섞일 수 있는 매물 감소를 체결량과 합산하지 않았습니다. 표본이 적거나 수집 중인 구간도 화면에 구분했습니다.

결과

72개 품목에서 73만 건 이상의 체결 기록을 축적하고, 가격·거래량·호가를 한 화면에서 비교하는 서비스를 운영했습니다. 예측 실험은 단순 기준선보다 오차가 커 기본 판단 지표와 분리했고, 후향 분석에서 발견한 4개 패턴은 판정 규칙을 먼저 고정한 전향 검증 FT1로 확인하고 있습니다.

수집된 체결 기록은 API에서 관측한 하한값이며 전체 거래량이 아닙니다. 요일별 차이와 이벤트 전후 변화도 현재는 관찰 결과로 제시하고, 통계적 유의성이나 원인으로 단정하지 않았습니다.

업무 연결

운영 담당자가 품목별 가격, 거래량, 매물과 이벤트 전후 변화를 데이터의 완전성과 함께 확인할 수 있는 기반을 만들었습니다. 수치의 정의와 한계를 화면에 같이 제시해 과도한 해석을 막고, 추가 확인이 필요한 이상 변화를 빠르게 찾도록 했습니다.

996개 문서와 3,925개 검색 단위, 20/32의 사람 검수 결과는 2026.08.07 데이터로 수행한 공식 평가 기록입니다. 이후 표 구조와 근거 검증을 개선하고 있으나, 변경된 작업본에 대한 새로운 독립 평가는 아직 진행하지 않았습니다.

문제

던전앤파이터 공식 정보가 여러 문서에 흩어져 있어 필요한 내용을 찾기 어렵고, 검색 결과가 있어도 답변 전체를 뒷받침하는지 따로 확인해야 했습니다.

역할

공식 문서 수집과 정제, 키워드·벡터 결합 검색, 근거 원문 복원, 답변 생성 기준과 웹 데모까지 하나의 흐름으로 구현했습니다.

판단 근거

평가 문항과 출력을 고정하고 답변을 근거 원문과 대조했습니다. 검색 실패, 잘못된 근거 선택, 생성·거절 실패를 구분하고, 개발 중 진단 결과와 공식 평가 결과를 따로 보고했습니다.

결과

별도 평가에서 사람 검수 기준으로 32문항 중 20문항이 통과했습니다. 사전에 정한 80% 기준에 미달해 기본 답변 방식으로 채택하지 않았고, 실패 유형과 재현 자료를 공개했습니다.

업무 활용

공식 문서를 빠르게 찾는 기능뿐 아니라 답변이 근거를 제대로 사용했는지 검증하는 절차까지 만들었습니다. 기준에 못 미친 결과는 그대로 공개해 활용 범위를 분명히 했습니다.

2026.07 · 개인 프로젝트 · 데이터 정제·모델링·검증·오차 집단 분석

Kaggle 대회용 합성 데이터 약 69만 행에서 LightGBM과 XGBoost를 비교했습니다. 전처리는 교차검증의 각 학습 구간 안에서만 수행해 데이터 누수를 막고, 결측 유형별 성능 차이도 따로 확인했습니다.

오차 분석과 모델 선택 수면시간 또는 스트레스 수준이 결측인 21.71%의 집단이 완전 성능 대비 오차 간극의 54.97%를 차지했습니다. 혼합 모델은 XGBoost보다 0.000086 높았지만 차이가 작고 과정이 복잡해 XGBoost 7-fold를 최종 선택했습니다.

분석 방식

무엇을 판단하기 위한 분석인지 먼저 정하고, 데이터 구조와 검증 기준을 만들어 결론과 한계를 함께 전달합니다. DNF 경매장 프로젝트에서는 다음 순서로 적용했습니다.

01

분석 질문 정하기

현재 체결 가격과 거래 활발도를 어떻게 보여줄지, 이벤트와 요일에 따라 나타난 차이를 어디까지 해석할 수 있는지 질문을 나눴습니다.

02

데이터 구조화

체결과 호가를 분리해 저장하고 원본 기록을 시간 단위로 집계했습니다. 아이템 특성에 따라 체결량 가중 가격과 단계별 최저 호가를 구분해 사용했습니다.

03

정합성과 품질 확인

API의 100건 한도에 자주 도달하는 품목은 수집 주기를 줄였습니다. 전체·품목별 최신성을 점검하고, 빈 관측과 당일 미완료 구간, 적은 표본을 화면에서 구분했습니다.

04

결과와 한계 함께 공개

예측은 단순 기준선과 비교해 성능을 확인한 뒤 실험값으로 분리했습니다. 요일 추세와 매물 변화도 인과관계로 단정하지 않고 실제 활용 범위를 함께 적었습니다.

결과값만 전달하지 않고 어떤 데이터와 기준을 사용했는지, 어디까지 해석할 수 있는지 함께 설명하겠습니다.
